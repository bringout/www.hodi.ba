Stalwart Mail Server podržava preusmjeravanje (forwarding) emailova putem Sieve skripti. U ovom postu opisujemo kako konfigurisati preusmjeravanje putem Stalwart management API-ja, bez potrebe za ponovnim buildanjem ili redeploymentom servera.

## Šta želimo postići

Kada korisnik primi email na adresu `korisnik@example.com`, želimo da se kopija tog emaila automatski proslijedi na `korisnik@drugi-domen.com`, a original zadrži u lokalnom sandučetu.

## Korak 1: Kreiranje Sieve skripte

Sieve skripta koristi `redirect :copy` direktivu koja prosljeđuje kopiju poruke na drugu adresu, dok original ostaje u sandučetu primaoca.

Ključni detalj: u Stalwart 0.15.x, sadržaj trusted Sieve skripte mora biti pohranjen pod ključem koji završava sa `.contents`. Na primjer:

```
sieve.trusted.scripts.moja-skripta.contents
```

Skripta izgleda ovako:

```sieve
require ["envelope", "redirect", "copy"];
if envelope :is "to" "korisnik@example.com" {
  redirect :copy "korisnik@drugi-domen.com";
}
```

## Korak 2: Postavljanje putem Management API-ja

Stalwart management API na portu 8080 prima POST zahtjeve na `/api/settings`. Format tijela zahtjeva je JSON niz objekata sa sljedećom strukturom:

```json
[
  {
    "type": "insert",
    "prefix": null,
    "values": [
      ["sieve.trusted.scripts.moja-skripta.contents",
       "require [\"envelope\", \"redirect\", \"copy\"]; if envelope :is \"to\" \"korisnik@example.com\" { redirect :copy \"korisnik@drugi-domen.com\"; }"]
    ],
    "assert_empty": false
  }
]
```

Važne napomene o API formatu:
- Polje `type` može biti `"insert"`, `"delete"` ili `"clear"`
- Polje `assert_empty` koristi **snake_case** (ne camelCase), iako dokumentacija može sugerisati drugačije
- Polje `values` je niz parova `["ključ", "vrijednost"]`
- Za brisanje ključeva koristi se: `{"type": "delete", "keys": ["ključ.za.brisanje"]}`

Primjer sa `curl`:

```bash
curl -X POST \
  -u admin:LOZINKA \
  -H "Content-Type: application/json" \
  -d '[{"type":"insert","prefix":null,"values":[["sieve.trusted.scripts.moja-skripta.contents","require [\"envelope\",\"redirect\",\"copy\"]; if envelope :is \"to\" \"korisnik@example.com\" { redirect :copy \"korisnik@drugi-domen.com\"; }"]],"assert_empty":false}]' \
  http://127.0.0.1:8080/api/settings
```

## Korak 3: Aktiviranje skripte u SMTP sesiji

Samo kreiranje skripte nije dovoljno — potrebno ju je povezati sa SMTP pipeline-om postavljanjem `session.data.script` na ime skripte.

**Važno**: Ime skripte mora biti u jednostrukim navodnicima jer Stalwart parsira vrijednost kao izraz. Bez navodnika, ime poput `moja-skripta` bi bilo interpretirano kao matematička operacija (varijabla `moja` minus varijabla `skripta`).

```json
[
  {
    "type": "insert",
    "prefix": null,
    "values": [
      ["session.data.script", "'moja-skripta'"]
    ],
    "assert_empty": false
  }
]
```

Nakon postavljanja, potrebno je restartovati Stalwart servis:

```bash
systemctl restart stalwart-mail
```

Provjerite startup logove za eventualne greške:

```bash
journalctl -u stalwart-mail --since "10 seconds ago" | grep -i "error\|script\|sieve"
```

Ako vidite grešku poput `Invalid variable or constant`, ime skripte nije pravilno navedeno u navodnicima.

## Korak 4: TLS konfiguracija za isporuku

Ako odredišni mail server ima istekli TLS certifikat, Stalwart će odbiti isporuku poruke. U logu ćete vidjeti:

```
STARTTLS error ... invalid peer certificate: certificate expired
```

Za omogućavanje isporuke na servere sa nevažećim certifikatima (opportunistic TLS):

```json
[
  {
    "type": "insert",
    "prefix": null,
    "values": [
      ["queue.outbound.tls.allow-invalid-certs", "true"]
    ],
    "assert_empty": false
  }
]
```

Ovo je uobičajena praksa na javnom internetu jer mnogi SMTP serveri imaju samopotpisane ili istekle certifikate. SMTP protokol je historijski dizajniran bez obaveznog TLS-a, pa je opportunistic pristup standard.

## Verifikacija

Nakon restarta, pošaljite testni email i pratite logove:

```bash
journalctl -u stalwart-mail -f | grep -v "tls.no-certificates\|auth.success"
```

Uspješno preusmjeravanje prepoznajete po log zapisu:

```
Queued autogenerated message for delivery ... to = ["korisnik@drugi-domen.com"]
```

## Pregled svih postavki

Za provjeru trenutnih Sieve postavki:

```bash
curl -s -u admin:LOZINKA \
  http://127.0.0.1:8080/api/settings/list?prefix=sieve.trusted
```

Za provjeru SMTP sesijskih postavki:

```bash
curl -s -u admin:LOZINKA \
  http://127.0.0.1:8080/api/settings/list?prefix=session.data
```

## Primjeri Sieve skripti

### Jednostavno preusmjeravanje sa lokalnom kopijom

```sieve
require ["envelope", "redirect", "copy"];
if envelope :is "to" "info@example.com" {
  redirect :copy "admin@drugi-domen.com";
}
```

### Preusmjeravanje bez zadržavanja lokalne kopije

```sieve
require ["envelope", "redirect"];
if envelope :is "to" "stara-adresa@example.com" {
  redirect "nova-adresa@drugi-domen.com";
}
```

### Preusmjeravanje na više adresa

```sieve
require ["envelope", "redirect", "copy"];
if envelope :is "to" "tim@example.com" {
  redirect :copy "clan1@example.com";
  redirect :copy "clan2@example.com";
  redirect :copy "clan3@example.com";
}
```

### Preusmjeravanje po domeni

```sieve
require ["envelope", "redirect", "copy"];
if envelope :domain :is "to" "stari-domen.com" {
  redirect :copy "catchall@novi-domen.com";
}
```

### Uslovno preusmjeravanje sa filtriranjem

```sieve
require ["envelope", "redirect", "copy", "header"];
if header :contains "Subject" "[URGENT]" {
  redirect :copy "hitno@example.com";
}
```

## Zaključak

Stalwart Mail Server pruža fleksibilan sistem za email preusmjeravanje putem Sieve skripti i management API-ja. Ključne stvari za zapamtiti:

1. Sadržaj skripte ide pod ključ sa `.contents` sufiksom
2. Referenca na skriptu u `session.data.script` mora biti u jednostrukim navodnicima
3. API koristi `assert_empty` (snake_case) u JSON formatu
4. Za isporuku na servere sa isteklim certifikatima, omogućite `allow-invalid-certs`
